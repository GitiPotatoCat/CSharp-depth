Dictionary<TKey, TValue>

A hash table — the cornerstone of fast lookup. Keyed access in expected O(1), at the cost of unpredictable iteration order and a dependence on a good GetHashCode(). Understand one data structure deeply and this is the one: it powers HashSet, ConcurrentDictionary, FrozenDictionary, and most of what your code actually spends its time on.

01Overview

A dictionary is a hash table: a mapping from keys to values where looking up a key takes expected constant time, no matter how many entries exist. You can have a million users and pulling up user #742,301 by id is (almost) as fast as pulling up user #1. No other built-in collection gives you that.

The trick is a hash function. Every key is reduced to an integer via GetHashCode(), that integer is reduced modulo the table's capacity to pick a bucket, and the entry is stored there. Lookup repeats the same computation to find the bucket. When two keys land in the same bucket — a collision — .NET chains the entries together, so the search within one bucket is linear. Keep collisions rare and the average stays O(1).

Namespace

Dictionary<TKey, TValue> lives in System.Collections.Generic. For concurrent producers and consumers: ConcurrentDictionary<TKey, TValue>. For read-optimised, immutable-after-build lookup: FrozenDictionary<TKey, TValue> (.NET 8+). For truly immutable with structural sharing: ImmutableDictionary<TKey, TValue>.

02Hash pipeline

Every read and write follows the same three-step pipeline. Once you see this, everything about hash tables — collisions, load factor, rehashing — falls into place.

Step 1 · Key
"apple"
→
Step 2 · Hash
0x7B3C9A2E
→
Step 3 · Bucket
[6]
hash("apple") = 0x7B3C9A2E  ·  0x7B3C9A2E % 8 = 6

Step 2 comes from key.GetHashCode() — a well-defined method on every .NET type. Step 3 is the runtime's responsibility: it reduces the hash modulo the current bucket-array length. If two keys produce the same hash (or simply collide in the same bucket), both entries live in that bucket, linked together — and lookup walks the chain.

Program.cs · a user registry 
using System.Collections.Generic;

var users = new Dictionary<int, string>();
users[101] = "Ada";
users[237] = "Grace";
users[512] = "Linus";

Console.WriteLine(users[237]);                 // "Grace"      — expected O(1)
Console.WriteLine(users.ContainsKey(999));      // False

// Idiomatic safe-access — no exceptions
if (users.TryGetValue(101, out var name))
    Console.WriteLine($"Hello, {name}");    // "Hello, Ada"

03Hash bucket playground

Watch a real hash table at work. Add keys and see exactly which bucket they land in. Keys that collide visibly chain in the same bucket. When the load factor exceeds 1.0, the entire table rehashes — the signature moment of any hash-based structure.

Watch for this

Add apple, banana, cherry, then keep going. Eventually two keys will land in the same bucket and the bucket border turns amber — a collision. Past 8 total entries (load factor > 1.0) the whole table rehashes to a larger capacity — you'll see the overlay pop up, entries fade, and then re-appear in new positions. That's the price of keeping the average lookup at O(1).

04Core operations

Eight methods carry essentially everything you'll do with a dictionary. The Try* variants are the modern default — they avoid both exceptions and double-lookups.

The indexer both reads and writes. Reading a missing key throws KeyNotFoundException — use TryGetValue unless you're certain the key exists.

Indexer [key]
var prices = new Dictionary<string, decimal>();

prices["apple"]  = 0.50m;        // set (creates if missing)
prices["banana"] = 0.30m;
prices["apple"]  = 0.55m;        // overwrites silently

decimal p = prices["apple"];      // 0.55 — reads

// Missing key throws:
// decimal x = prices["grape"];   // KeyNotFoundException

Add insists the key is new — throws if it already exists. Use it when a duplicate would be a bug.

Add — strict insert
var registry = new Dictionary<int, string>();
registry.Add(101, "Ada");             // ok
registry.Add(102, "Grace");           // ok

// Duplicate throws — Add refuses to overwrite
// registry.Add(101, "Other");    // ArgumentException

// Use the indexer for upsert:
registry[101] = "Lovelace";         // quietly overwrites

The modern default for reading. One lookup, no exception, and you can handle “missing” with a clean if.

TryGetValue — exception-free read
var config = new Dictionary<string, string>
{
    ["host"] = "localhost",
    ["port"] = "5432",
};

if (config.TryGetValue("host", out var host))
    Console.WriteLine($"Connecting to {host}");

// Default if missing, one lookup:
string tz = config.GetValueOrDefault("timezone", "UTC");

TryAdd returns false if the key already exists instead of throwing. Perfect for deduplication during ingestion.

TryAdd — dedup-friendly insert
var seen = new Dictionary<string, int>();

foreach (var word in words)
{
    // Count first occurrence only
    if (seen.TryAdd(word, seen.Count + 1))
        Console.WriteLine($"first: {word}");
}

Returns true if the key was present and removed. A second overload also returns the removed value — useful when you need to do something with it.

Remove — with and without value-out
var cache = new Dictionary<string, byte[]>();
cache["avatar.png"] = fileBytes;

bool removed = cache.Remove("avatar.png");   // true

// Get-and-remove in one step
if (cache.Remove("old-key", out var evicted))
    Cleanup(evicted);

Returns whether a key is present — without fetching its value. Slightly faster than TryGetValue when you don't need the value.

ContainsKey
var bans = new Dictionary<string, DateTime>();

// Just a presence check — no value needed
if (bans.ContainsKey(user.Email))
    return Forbid();

// If you DO need the value, fold into one lookup:
if (bans.TryGetValue(user.Email, out var until))
    return Forbid(until);

Enumeration yields KeyValuePair<TKey, TValue>. The order is undocumented — current .NET follows insertion order, but don't rely on this.

foreach / Keys / Values
var d = new Dictionary<string, int>
{
    ["apple"] = 1, ["banana"] = 2, ["cherry"] = 3,
};

// KeyValuePair enumeration
foreach (var kvp in d)
    Console.WriteLine($"{kvp.Key} → {kvp.Value}");

// Destructuring (C# 7+)
foreach (var (k, v) in d)
    Console.WriteLine($"{k} → {v}");

// Iterate just keys or just values
foreach (var k in d.Keys)   Console.Write(k);
foreach (var v in d.Values) Console.Write(v);

05Complexity matrix

Get [k] O(1)O(n)Worst case = bad hash, everything collides

Add O(1)O(n)Same as Set, but throws on duplicate key
TryGetValue / ContainsKey O(1)O(n)Hash then walk chain
Remove O(1)O(n)Hash then unlink from chain
ContainsValue O(n)O(n)Must scan every entry — no value index
Enumeration O(n)O(n)Walks all non-empty slots
Count O(1)O(1)Cached
Clear O(n)O(n)Zeroes the bucket array
Amortised O(1)

Insertions are amortised O(1): occasionally one insertion triggers a rehash and pays O(n), but those are rare enough that when you average the cost across many insertions, it's still constant per op. The same trick that makes List<T>'s Add cheap.

Worst-case O(n)

If every key hashes to the same bucket — because the hash function is bad or an attacker is crafting keys to collide on purpose — every operation degrades to O(n). This is known as hash flooding and is why server code should use randomised hashing for untrusted input. .NET strings already randomise per-process, but custom GetHashCode() implementations must take care.

06When to choose which

Dictionary<TKey, TValue> is the default for any key-indexed lookup. The decision is usually between it and one of its specialised cousins.

Pick Dictionary<TKey, TValue>

Fast keyed lookup · default
  • Mapping ids to records, names to settings
  • Counting occurrences (word → count)
  • Caching computed results keyed by input
  • Joining two data sources in memory
  • Any time list.Find(x => x.Id == id) shows up in a loop

Pick a specialised variant

Same shape · different trade-offs
  • HashSet<T> — keys only, no values
  • ConcurrentDictionary<TKey, TValue> — thread-safe writes
  • FrozenDictionary<TKey, TValue> — read-only, fastest reads (.NET 8+)
  • ImmutableDictionary<TKey, TValue> — persistent, structural sharing
  • SortedDictionary<TKey, TValue> — key-ordered iteration, O(log n)
Best practice · pre-size when you can

If you know you're about to insert 10,000 items, say so: new Dictionary<int, User>(capacity: 10_000). You'll skip every intermediate rehash along the way. Same idea as List, but the savings are bigger — each rehash is O(n), not just an array copy.

07Custom key equality

A dictionary is only as good as its keys' GetHashCode() and Equals() implementations. Strings, primitives, and records get this right out of the box. Your own classes don't.

Three ways to get key equality right 
// ① Records — free, correct, recommended default
public record UserKey(string TenantId, int UserId);

var perms = new Dictionary<UserKey, string[]>();
perms[new UserKey("acme", 42)] = ["read", "write"];
// record GetHashCode() combines all properties automatically

// ② Value tuples — also free equality, lighter weight
var scores = new Dictionary<(int x, int y), int>();
scores[(5, 3)] = 10;

// ③ IEqualityComparer<T> — for case-insensitive string keys etc.
var caseInsensitive = new Dictionary<string, int>(
    StringComparer.OrdinalIgnoreCase);
caseInsensitive["Apple"] = 1;
Console.WriteLine(caseInsensitive["APPLE"]);   // 1

// ④ Manual — when you need full control
public class Point : IEquatable<Point>
{
    public required int X { get; init; }
    public required int Y { get; init; }

    public bool Equals(Point? other) =>
        other is not null && X == other.X && Y == other.Y;

    public override int GetHashCode() =>
        HashCode.Combine(X, Y);

    public override bool Equals(object? obj) => Equals(obj as Point);
}
The golden rule of hash keys

A key's hash code must not change while it's in the dictionary. If you mutate a field that GetHashCode() uses after inserting the key, the entry becomes invisible — the dictionary will look for it in the wrong bucket and not find it. Keep keys immutable, or copy the relevant fields into an immutable record before use.

Equals and GetHashCode must agree

If a.Equals(b) == true, then a.GetHashCode() == b.GetHashCode() must also be true. The reverse need not hold (unequal objects can share a hash). Records enforce this automatically; manual implementations often don't and produce deeply confusing bugs.

08Modern C# 14 idioms

The Dictionary API has been stable for years, but collection expressions, FrozenDictionary, and the CollectionsMarshal.GetValueRefOrAddDefault trick have all reshaped what idiomatic dictionary code looks like.

Modern idioms · C# 14 on .NET 10 
// ① Collection expressions (with KeyValuePair literals)
Dictionary<string, int> scores = new()
{
    ["alice"] = 95,
    ["bob"]   = 82,
    ["carol"] = 77,
};

// ② Deconstruction in foreach — idiomatic since C# 7
foreach (var (name, score) in scores)
    Console.WriteLine($"{name}: {score}");

// ③ FrozenDictionary — build once, read many (.NET 8+)
var frozen = scores.ToFrozenDictionary();
int bob = frozen["bob"];      // ~30% faster reads than Dictionary
// frozen["dave"] = 99;           // compile error — immutable

// ④ GetValueRefOrAddDefault — zero-lookup counter pattern
using System.Runtime.InteropServices;

var counts = new Dictionary<string, int>();
foreach (var word in words)
{
    ref int c = ref CollectionsMarshal
        .GetValueRefOrAddDefault(counts, word, out _);
    c++;          // one hash lookup for the whole increment
}

// ⑤ Primary constructor — bounded cache in 10 lines
public class MemoCache<K, V>(int capacity) where K : notnull
{
    private readonly Dictionary<K, V> _store = new(capacity);

    public V GetOrAdd(K key, Func<K, V> factory)
    {
        if (!_store.TryGetValue(key, out var v))
            _store[key] = v = factory(key);
        return v;
    }
}
FrozenDictionary · .NET 8+

If you build a lookup once and then read from it thousands of times per second, ToFrozenDictionary() can cut read latency by roughly 20-40%. The build is more expensive — it pre-computes an optimal hash layout — but every read afterwards is faster. Ideal for route tables, config lookups, and compile-time-like data that ships with your app.

09Pitfalls

Pitfall 01 · Indexer throws on missing key

dict[missingKey] throws KeyNotFoundException. Always prefer TryGetValue unless you've already checked with ContainsKey — and even then, TryGetValue is preferred because it does a single lookup instead of two.

Pitfall 02 · Enumeration order is undefined

Iteration order is unspecified by contract. Current .NET happens to preserve insertion order for Dictionary<TKey, TValue>, but relying on this is a time bomb — it can change across runtime versions, and it explicitly won't hold for FrozenDictionary or ImmutableDictionary. If you need order, sort explicitly or use SortedDictionary<TKey, TValue>.

Pitfall 03 · Mutating a key after insertion

If the key's GetHashCode() uses a field that you later change, the entry becomes unreachable. This is why reference types with mutable fields are dangerous keys. Use record, ValueTuple, or a readonly wrapper.

Pitfall 04 · Modifying during enumeration

Adding or removing entries during a foreach throws InvalidOperationException. Collect the keys you want to change into a separate list first, then mutate in a second pass — or use .Where(...).ToList() if you're filtering.

Not thread-safe

Dictionary<TKey, TValue> is safe for multiple concurrent readers only if there are zero writers. One writer plus one reader is already a race. For concurrent writes reach for ConcurrentDictionary<TKey, TValue> — it uses fine-grained locking and provides atomic primitives like GetOrAdd and AddOrUpdate.
