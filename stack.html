Stack<T>

Last-in, first-out. A disciplined collection where you only touch the top of the pile — Push to add, Pop to take, Peek to look. It powers undo buffers, expression parsers, depth-first traversals, and every balanced-bracket check ever written.

01Overview

A stack is the computing world's most disciplined collection. It exposes only three operations that matter — Push, Pop, and Peek — and all three work on the top of the pile. Items added most recently are the first to come back out, hence LIFO: last in, first out.

That constraint is the feature. When you need to remember “what was I doing just before this?” — a function return address, the previous browser page, an undo step, an unclosed bracket — a stack gives you the answer in O(1) and throws away everything else.

Namespace

Stack<T> lives in System.Collections.Generic. Internally it's backed by a resizable array — not a linked list — so it shares List<T>'s capacity-doubling behaviour. For lock-free concurrent use, reach for ConcurrentStack<T>.

Program.cs · building and inspecting the pile 
using System.Collections.Generic;

var undo = new Stack<string>();
undo.Push("typed 'Hello'");
undo.Push("typed ' world'");
undo.Push("changed colour");

Console.WriteLine(undo.Count);       // 3
Console.WriteLine(undo.Peek());      // "changed colour"  — top, not removed
Console.WriteLine(undo.Pop());       // "changed colour"  — removes top
Console.WriteLine(undo.Pop());       // "typed ' world'"
Console.WriteLine(undo.Count);       // 1

04Core operations

Six methods cover every real-world use. Note especially the Try* variants — they are the modern, exception-free way to access a stack.

Pushes a value onto the top. The internal array doubles if it runs out of capacity — same strategy as List<T>.

Push / add to top
var calls = new Stack<string>();
calls.Push("Main()");
calls.Push("LoadConfig()");
calls.Push("ReadFile()");

// Top → ReadFile, then LoadConfig, then Main
Console.WriteLine(calls.Count);         // 3

Removes and returns the top. Throws InvalidOperationException if empty — always prefer TryPop unless you're certain there's something there.

Pop / remove top
var history = new Stack<string>(["home", "about", "contact"]);
// Collection expression puts "contact" on top (last item wins)

string back = history.Pop();       // "contact"
Console.WriteLine(history.Count);     // 2

// Stack throws if empty — this is the dangerous overload
var empty = new Stack<int>();
// empty.Pop();   // InvalidOperationException!

Returns the top without removing it. Ideal for “what's next?” inspection during parsing or pathfinding.

Peek / inspect top
var parens = new Stack<char>();
parens.Push('(');
parens.Push('[');

char expected = parens.Peek();      // '['  — still on the pile
Console.WriteLine(parens.Count);        // 2     — unchanged

The modern, non-throwing variants. Added in .NET Core 2.0 and now idiomatic for any code that can't assume the stack is non-empty.

TryPop / TryPeek
var stack = new Stack<int>();
stack.Push(42);

// Safe pop
if (stack.TryPop(out int val))
    Console.WriteLine($"popped {val}");      // popped 42

// Safe peek on empty stack — no exception
if (!stack.TryPeek(out int top))
    Console.WriteLine("stack is empty");       // prints this

Linear scan from top to bottom. If you're calling Contains often, you probably want a HashSet<T> alongside.

Contains · linear search
var visited = new Stack<int>();
visited.Push(1);
visited.Push(2);
visited.Push(3);

bool seen = visited.Contains(2);    // true — O(n)

// For repeated membership checks, pair the stack with a HashSet
var seenSet = new HashSet<int>();

Iteration walks from top to bottom — not insertion order. A frequent surprise for newcomers.

foreach / ToArray / ToList
var nums = new Stack<int>();
nums.Push(1);
nums.Push(2);
nums.Push(3);

foreach (var n in nums)
    Console.Write(n);            // 321  — top to bottom, NOT 123

int[] snapshot = nums.ToArray();
// snapshot: [3, 2, 1]  — also top-first

Under the hood

Stack<T> is backed by a regular array that grows by doubling — the same mechanism as List<T>. It's not a linked structure. This means excellent cache behaviour for iteration, but the occasional O(n) copy when capacity runs out. Pre-size with new Stack<int>(capacity: 1024) if you know the ceiling.

06When to choose which

A stack is rarely the wrong answer when the problem shape matches — but the shape has to match. Two questions decide it: do you care about ordering, and does your code ever need to look anywhere but the top?

Pick Stack<T>

LIFO · top-only
  • Undo & redo buffers
  • Balanced-bracket / expression parsing
  • Depth-first search (DFS) of graphs and trees
  • Backtracking algorithms (N-queens, maze solvers)
  • Simulating a call stack or nested scopes
  • Browser back button (one of two stacks)

Pick Queue<T> instead

FIFO · the opposite discipline
  • Fair scheduling — oldest waits shortest
  • Breadth-first search (BFS) of graphs
  • Producer / consumer message buffers
  • Print queues, task queues, event pipelines
  • Any time arrival order must be preserved
  • See — Module 04
Best practice

If you find yourself calling Contains or ToArray on a stack repeatedly, the stack is probably the wrong shape for your data. Reach for a List<T> or a HashSet<T> alongside.

07Brackets validator

The canonical stack problem. For every opening bracket push it; for every closing bracket pop and check the pair matches. The string is balanced if and only if the stack ends empty — and no pop ever mismatched.

The algorithm, 12 lines 
static bool IsBalanced(string s)
{
    var stack = new Stack<char>();
    var pairs = new Dictionary<char, char>
        { [')']='(', [']']='[', ['}']='{' };

    foreach (var c in s)
    {
        if (c is '(' or '[' or '{')
            stack.Push(c);
        else if (pairs.TryGetValue(c, out var open))
        {
            if (!stack.TryPop(out var top) || top != open)
                return false;
        }
    }
    return stack.Count == 0;
}
Why this is elegant

Twelve lines. No recursion. Handles arbitrary nesting depth. The stack is acting as a memory — it remembers every opener in reverse order, exactly the order the matching closers must arrive. Every other “how deep are we?” problem has this shape somewhere.

08Modern C# 14 idioms

The Stack<T> API has barely changed, but the surrounding language keeps refining what idiomatic stack code looks like.

Modern idioms · C# 14 on .NET 10 
// ① Collection expressions — note the order
Stack<int> stack = new([1, 2, 3]);
//     3 ends up on top (items pushed in sequence)

// ② TryPop with pattern matching — no exceptions, no null checks
while (stack.TryPop(out var item))
    Console.WriteLine(item);      // 3, 2, 1

// ③ Spread into array — captures current top-to-bottom view
var history = new Stack<string>();
history.Push("a"); history.Push("b"); history.Push("c");
string[] snapshot = [.. history];     // ["c", "b", "a"]

// ④ Primary constructor — bounded undo buffer in 10 lines
public class UndoBuffer<T>(int capacity)
{
    private readonly Stack<T> _items = new();
    public int Count => _items.Count;

    public void Record(T action)
    {
        if (_items.Count == capacity)
            _items = new(_items.Take(capacity - 1).Reverse());
        _items.Push(action);
    }
    public bool TryUndo(out T? action) => _items.TryPop(out action);
}

09Pitfalls

Pitfall 01 · Pop on empty throws

Pop() and Peek() both throw InvalidOperationException when the stack is empty. In modern code, always prefer TryPop / TryPeek unless you have a hard invariant that guarantees the stack is non-empty.

Pitfall 02 · Iteration order is LIFO

foreach, ToArray, and ToList all walk from top to bottom — newest first. If you need insertion order, either reverse the result or use a List<T>. Debuggers often display stacks the same way, which can confuse newcomers.

Pitfall 03 · Collection expression order

new Stack<int>([1, 2, 3]) ends up with 3 on top, not 1. Items are pushed in the order given, so the last one wins. This is consistent with new Stack<int>(enumerable) behaviour — but counter-intuitive if you read left-to-right.

Pitfall 04 · Capacity never shrinks on Pop

The internal array keeps its capacity even after extensive popping. Call TrimExcess() if long-lived stacks must release memory — otherwise they hold onto the high-water mark forever.

Not thread-safe

Stack<T> is not safe for concurrent writes. For multi-threaded scenarios use ConcurrentStack<T> from System.Collections.Concurrent — it offers lock-free Push, TryPop, and TryPeek with the same API shape.
