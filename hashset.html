HashSet<T>

Dictionary without the values. Uniqueness, membership testing, and the algebra of sets — union, intersection, difference, symmetric difference — all backed by the same hash table that makes Dictionary fast. The quietest, most reusable collection in the BCL.

01Overview

A HashSet<T> is a collection of unique elements. That's the whole premise: you can Add an item, and if it's already there the call silently returns false and changes nothing. Membership testing is expected O(1) — the same hash-table magic that powers Dictionary<TKey, TValue>, just without the values.

Any time you catch yourself writing if (!list.Contains(x)) list.Add(x), stop — that pattern is a HashSet<T> wearing a costume. The cost goes from O(n) per duplicate check on a list to O(1) on a set, and the intent of “no duplicates” becomes declarative instead of procedural.

Namespace

HashSet<T> lives in System.Collections.Generic. It implements ISet<T> and IReadOnlySet<T>. For concurrent, thread-safe use: ConcurrentDictionary<T, byte> (there's no built-in ConcurrentHashSet in .NET). For immutable, read-optimised: FrozenSet<T> (.NET 8+).

02Uniqueness anatomy

Every item that arrives is hashed, bucketed, and compared against what's already there. Duplicates are silently dropped. The order items entered is not remembered — enumeration order is unspecified, though in practice modern .NET preserves insertion order.

apple → banana → apple → cherry → banana
⇒
{ apple, banana, cherry }
Program.cs · deduplicating a stream 
using System.Collections.Generic;

string[] stream = ["apple", "banana", "apple", "cherry", "banana"];
var seen = new HashSet<string>();

foreach (var word in stream)
{
    // Add returns false if the item was already present
    if (seen.Add(word))
        Console.WriteLine($"first occurrence: {word}");
}

Console.WriteLine(seen.Count);               // 3
Console.WriteLine(seen.Contains("apple"));    // True — O(1) avg

04Core operations

Five methods handle practically every non-set-algebra use. For read-only checks, Contains is the operation you'll reach for most.

Returns true if the item was new, false if it was already present. Unlike Dictionary.Add, it never throws on duplicates.

Add — dedup-friendly
var emails = new HashSet<string>(StringComparer.OrdinalIgnoreCase);

emails.Add("ada@example.com");       // true  — new
emails.Add("grace@example.com");     // true  — new
emails.Add("ADA@example.com");       // false — case-insensitive dupe

Console.WriteLine(emails.Count);         // 2

The signature HashSet operation. If your code does membership checks in a loop, this is the method that makes it fast.

Contains — O(1) membership
var banned = new HashSet<string> { "spam", "bot", "abuse" };

foreach (var comment in comments)
    if (banned.Contains(comment.Category))    // O(1) avg
        Hide(comment);

// Compare: list.Contains(...) would be O(n) PER comment → O(n×m)
// HashSet.Contains(...) is O(1) PER comment → O(m) total

Returns true if the item was present and removed, false otherwise. Never throws.

Remove
var active = new HashSet<int> { 101, 102, 103 };

bool removed = active.Remove(102);    // true
bool again   = active.Remove(102);    // false — not there any more

Console.WriteLine(active.Count);       // 2

// RemoveWhere for bulk conditional removal
int dropped = active.RemoveWhere(x => x > 102);   // 1

A subtle method. For reference-type keys, different instances can be equal yet distinct. TryGetValue retrieves the stored instance, which you can then use as a canonical reference.

TryGetValue — canonicalisation trick
var interns = new HashSet<string>();

string Intern(string s)
{
    // Return the existing instance if we've seen this string before
    if (interns.TryGetValue(s, out var canonical))
        return canonical;
    interns.Add(s);
    return s;
}

// Now a and b share the SAME reference, not just equal strings
var a = Intern("hello");
var b = Intern("hello");
Console.WriteLine(ReferenceEquals(a, b));  // True

Walk every element. Order is undocumented — do not rely on it. For sorted iteration, use SortedSet<T> instead.

foreach / LINQ
var tags = new HashSet<string> { "csharp", "dotnet", "data" };

foreach (var t in tags)
    Console.WriteLine(t);            // order not guaranteed

// Need sorted output? Two good options:
foreach (var t in tags.OrderBy(x => x))   // ad-hoc
    Console.WriteLine(t);

var sorted = new SortedSet<string>(tags);    // permanent

05Set algebra

Four mutating set operations. Each modifies the calling set in place; none touches the argument. If you need non-mutating versions, LINQ's Union, Intersect, and Except return new sequences rather than modifying either source.

The four methods · what each keeps 
var a = new HashSet<int> { 1, 2, 3, 4 };
var b = new HashSet<int> { 3, 4, 5, 6 };

// ① UnionWith — A ← A ∪ B  — keep everything from either
// a → {1, 2, 3, 4, 5, 6}
a.UnionWith(b);

// ② IntersectWith — A ← A ∩ B  — keep only items present in both
// a → {3, 4}
a.IntersectWith(b);

// ③ ExceptWith — A ← A − B  — keep only items NOT in B
// a → {1, 2}
a.ExceptWith(b);

// ④ SymmetricExceptWith — A ← A △ B  — keep items in exactly one set
// a → {1, 2, 5, 6}
a.SymmetricExceptWith(b);

There are also five predicate methods that answer questions without modifying anything:

Five set-relationship checks 
var vowels = new HashSet<char> { 'a', 'e', 'i', 'o', 'u' };
var letters = new HashSet<char> { 'a', 'e', 'i', 'o', 'u', 'b', 'c' };

vowels.IsSubsetOf(letters);       // true  — every vowel is in letters
vowels.IsProperSubsetOf(letters); // true  — and letters has more
letters.IsSupersetOf(vowels);    // true  — mirror of above
vowels.Overlaps(letters);        // true  — at least one common
vowels.SetEquals(letters);       // false — different sizes

The payoff

A nested-loop deduplication with List.Contains is O(n²). The same algorithm with HashSet.Contains is O(n). On 10,000 items that's the difference between 10,000 operations and 100,000,000. This is why HashSet<T> is one of the most impactful single-line refactors you can apply to slow code.

07When to choose which

HashSet<T> shines when you need uniqueness or fast membership. The decision is usually between it and one of its specialised cousins.

Pick HashSet<T>

Uniqueness · membership
  • Deduplicating a stream of items
  • “Have I seen this already?” in a loop
  • Tracking visited nodes in graph algorithms (BFS/DFS)
  • Tag clouds, permission sets, enabled flags
  • Pairing with Queue<T> to dedup in BFS
  • Anywhere you wrote list.Distinct().ToList()

Pick a specialised variant

Same shape · different trade-offs
  • SortedSet<T> — ordered iteration, O(log n)
  • FrozenSet<T> — immutable, fastest reads (.NET 8+)
  • ImmutableHashSet<T> — persistent, structural sharing
  • Dictionary<TKey, TValue> — if values matter too
  • ConcurrentDictionary<T, byte> — closest to a thread-safe set
The most common refactor

If your code contains if (!list.Contains(x)) list.Add(x) or items.Distinct().ToList(), change the collection to HashSet<T>. You'll lose indexed access (list[i]) and insertion-order guarantees, but most code that checks membership doesn't need either. The speedup is often dramatic.

08Modern C# 14 idioms

Collection expressions, FrozenSet, and pattern-matched TryGetValue have all reshaped what idiomatic set code looks like in .NET 10.

Modern idioms · C# 14 on .NET 10 
// ① Collection expressions — duplicates silently dropped
HashSet<int> odds = [1, 3, 5, 3, 1];
// odds.Count == 3  — {1, 3, 5}

// ② Spread to combine — union without mutating
HashSet<int> primes = [2, 3, 5];
HashSet<int> evens  = [2, 4, 6];
HashSet<int> combined = [.. primes, .. evens];  // {2, 3, 4, 5, 6}

// ③ FrozenSet — build once, check many (.NET 8+)
using System.Collections.Frozen;

FrozenSet<string> reserved = new[]
{
    "class", "struct", "record", "interface",
    "namespace", "using", "void", "static"
}.ToFrozenSet();

bool isKeyword = reserved.Contains(token);  // ~30% faster than HashSet

// ④ TryGetValue for canonical instance (string interning, etc.)
if (interns.TryGetValue(candidate, out var canonical))
    return canonical;

// ⑤ Primary constructor — typed tag registry
public class TagSet(IEqualityComparer<string>? cmp = null)
{
    private readonly HashSet<string> _tags =
        new(cmp ?? StringComparer.OrdinalIgnoreCase);

    public bool Toggle(string tag) =>
        _tags.Add(tag) || !_tags.Remove(tag);   // add or remove in one call

    public IReadOnlySet<string> Snapshot() => _tags.ToFrozenSet();
}
FrozenSet · .NET 8+

For sets that you build once and query many times — keyword tables, feature flags, allowed-values lists — ToFrozenSet() produces a read-only set with roughly 20–40% faster Contains than HashSet<T>. The build cost is higher; the payoff is every subsequent lookup.

09Pitfalls

Pitfall 01 · Enumeration order is unspecified

Don't rely on the order items come out of foreach matching the order they went in. Current .NET happens to preserve insertion order in some cases, but this isn't guaranteed by contract and explicitly doesn't hold for FrozenSet or ImmutableHashSet. If order matters, sort explicitly or use SortedSet<T>.

Pitfall 02 · Set operations mutate the caller

a.UnionWith(b) modifies a in place — b is unchanged. If you want a new set without touching either, use LINQ: var c = a.Union(b).ToHashSet(). This is the opposite of LINQ's behaviour, and the naming similarity is a constant source of bugs.

Pitfall 03 · Custom types need equality

Same rules as Dictionary<TKey, TValue>: your element type's GetHashCode() and Equals() must agree, and must not change after insertion. Records and value tuples handle this automatically; classes with mutable fields are dangerous set members.

Pitfall 04 · No indexer, no random access

set[i] does not compile. To grab the “third item” you have to enumerate — and iteration order isn't guaranteed. If you find yourself reaching for indexed access, you probably want a List<T> with parallel deduplication, or SortedSet<T> for an ordered first-element via Min/Max.

No built-in ConcurrentHashSet

.NET has never shipped a ConcurrentHashSet<T>. The idiomatic workaround is ConcurrentDictionary<T, byte> where you ignore the value — add with TryAdd(key, 0), check with ContainsKey. It's not pretty, but it's lock-free and works.
