ConcurrentQueue<T>

A fully lock-free, thread-safe FIFO queue. Producers and consumers operate independently without serializing on a single lock — both ends move via interlocked operations. Backed by a linked list of fixed-size array segments that allocate only when the queue grows, keeping memory pressure low under steady-state load.

When to use

Reach for ConcurrentQueue whenever producers and consumers run on different threads and the order of delivery matters — worker pipelines, background job lists, log buffers drained by a flusher, asynchronous event dispatch. When consumers should wait until work arrives rather than poll, wrap this queue in BlockingCollection<T> or use Channel<T>. For LIFO semantics pick ConcurrentStack<T>, and for work-stealing-style scenarios use ConcurrentBag<T>.

How it works

dequeue ◄──┐ ┌── enqueue │ │ ▼ ▼ ┌────────────┐ ┌────────────┐ ┌────────────┐ │ segment 0 │→ │ segment 1 │→ │ segment 2 │ │ [_][a][b] │ │ [c][d][e] │ │ [f][_][_] │ └────────────┘ └────────────┘ └────────────┘ head tail linked list of fixed-size array segments. heads and tails advance via Interlocked.CompareExchange.
Count is approximate
Accessing Count walks every segment and — because producers and consumers are still moving during the walk — the returned value can be wrong the moment it is read. Treat it as diagnostic only. Use IsEmpty for cheap emptiness checks, and drain in a while (TryDequeue(...)) loop rather than gating on Count.

Example

// Construct — optionally seeded from any IEnumerable
var jobs = new ConcurrentQueue<string>();

// Enqueue — lock-free on the tail
jobs.Enqueue("fetch");
jobs.Enqueue("parse");
jobs.Enqueue("write");

// TryDequeue — lock-free, returns false when empty
while (jobs.TryDequeue(out var job))
    Process(job);

// TryPeek — snapshot read of the head
if (jobs.TryPeek(out var head))
    Console.WriteLine(head);

// Producer and consumer running in parallel — no locks needed
var producer = Task.Run(() =>
{
    for (int i = 0; i < 1_000; i++)
        jobs.Enqueue($"job-{i}");
});

var consumer = Task.Run(() =>
{
    while (!producer.IsCompleted || !jobs.IsEmpty)
        if (jobs.TryDequeue(out var j))
            Process(j);
});

await Task.WhenAll(producer, consumer);

// Point-in-time snapshot — iteration order is head → tail
string[] snapshot = jobs.ToArray();

// IEnumerable iteration — weakly consistent
foreach (var j in jobs)
    Console.WriteLine(j);
