BlockingCollection<T>

A coordination layer that wraps any IProducerConsumerCollection<T> — Queue, Stack, or Bag — with blocking Take and bounded Add. Consumers block when the collection is empty; producers block when a bounded collection is full. Add CompleteAdding and GetConsumingEnumerable, and you have a full producer-consumer pipeline in a few lines.

Add
O(1)
amortized; blocks when bounded and full
Take
O(1)
amortized; blocks when empty
Try…
O(1)
timed or non-blocking

When to use

Reach for BlockingCollection when producers and consumers are separate threads, consumers must wait for work to arrive, and you want built-in support for signaling completion. Perfect for ingest pipelines, thread-pool feeder loops, pre-async background workers, and log writers. In new async code, prefer Channel<T> — it exposes the same semantics without blocking threads. Use ConcurrentQueue directly when consumers can poll or when blocking is not needed.

Prefer Channel<T> in new async code
Every BlockingCollection operation blocks a thread-pool thread while waiting. In modern async systems this can starve the pool under load — one blocked consumer per queue costs a worker thread that could be doing useful work. System.Threading.Channels.Channel<T> offers the same bounded-queue semantics with await-based reads and writes. BlockingCollection remains the right choice for legacy synchronous pipelines and scenarios that must integrate with blocking APIs.

Example

// Default — wraps ConcurrentQueue, unbounded
var jobs = new BlockingCollection<string>();

// Bounded — Add blocks once full
var bounded = new BlockingCollection<string>(boundedCapacity: 100);

// Wrap a specific underlying collection
var stackBased = new BlockingCollection<string>(
    new ConcurrentStack<string>(), boundedCapacity: 50);

// Producer — signals done at the end
var producer = Task.Run(() =>
{
    for (int i = 0; i < 1_000; i++)
        jobs.Add($"job-{i}");        // may block if bounded and full

    jobs.CompleteAdding();              // unblocks pending consumers
});

// Consumer — loops until completion signal
var consumer = Task.Run(() =>
{
    foreach (var job in jobs.GetConsumingEnumerable())
        Process(job);                   // exits when IsCompleted
});

await Task.WhenAll(producer, consumer);

// Timed and cancellable operations
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
if (jobs.TryTake(out var item, TimeSpan.FromMilliseconds(500)))
    Process(item);

jobs.TryAdd("urgent", TimeSpan.FromSeconds(1), cts.Token);

// Multi-collection dispatch — take from whichever is ready first
BlockingCollection<string>[] farms = [high, medium, low];
int idx = BlockingCollection<string>.TakeFromAny(farms, out var taken);
