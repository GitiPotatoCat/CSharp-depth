SortedList<TKey, TValue>

A sorted key-value map backed by two parallel arrays — one of keys, one of values. Compact in memory, fast to read via binary search, and uniquely able to be addressed by both key and numeric index. The tradeoff: every insert that lands in the middle shifts the tail of both arrays.

Lookup
O(log n)
binary search on keys
Insert
O(n)
shift to preserve order
Delete
O(n)
shift after removal

When to use

Pick SortedList when the data is mostly written once and then read repeatedly — configuration tables, lookup grids, leaderboards built from a known dataset. It uses less memory than SortedDictionary and searches faster, but every mid-sequence write costs O(n). If inserts and removes happen often, SortedDictionary is the right call. If ordering does not matter, Dictionary beats both.

How it works

index: 0 1 2 3 4 ┌───────┬───────┬───────┬───────┬───────┐ keys: │ Alice │ Bob │ Carol │ Dan │ Eve │ ◄── binary search ├───────┼───────┼───────┼───────┼───────┤ values: │ 88 │ 72 │ 95 │ 91 │ 84 │ └───────┴───────┴───────┴───────┴───────┘ two parallel arrays, kept sorted by key. read by key → O(log n), or by index → O(1).
Dual addressing
Unlike Dictionary and SortedDictionary, SortedList exposes an integer index alongside the key. That means you can ask for the third smallest key in O(1) via GetKeyAtIndex or iterate by position. This is genuinely useful for pagination, rank queries, and windowed traversal — and it is the one thing SortedList does that the other sorted map cannot.

Example

// Create — collection initializer sorts on insert
var scores = new SortedList<string, int>
{
    ["Dan"]   = 91,
    ["Alice"] = 88,
    ["Carol"] = 95
};

// Preallocate when size is known — avoids array resizes
var big = new SortedList<int, string>(capacity: 10_000);

// O(log n) lookup by key
if (scores.TryGetValue("Alice", out var s))
    Console.WriteLine(s);

// O(1) access by position — unique to SortedList
string thirdName  = scores.GetKeyAtIndex(2);
int    thirdScore = scores.GetValueAtIndex(2);

// Locate index of a key
int idx = scores.IndexOfKey("Carol");        // O(log n)
int vix = scores.IndexOfValue(91);            // O(n)

// Insert — O(n) because the tail shifts
scores["Bob"] = 72;

// Remove by key or by index
scores.Remove("Bob");
scores.RemoveAt(0);                            // drop the smallest

// Enumeration yields KeyValuePair in key order
foreach (var (name, score) in scores)
    Console.WriteLine($"{name}: {score}");

SortedList vs SortedDictionary

AspectSortedList<K,V>SortedDictionary<K,V>
BackingTwo parallel arrays — keys and values.Red-black binary search tree.
MemoryCompact — one pair of arrays, no per-node pointers.Heavier — each entry is a node with left, right, parent, color.
LookupO(log n) with cache-friendly binary search.O(log n) with pointer chasing across nodes.
Insert / deleteO(n) — shifts the tail of both arrays.O(log n) — rotates to rebalance.
Index by positionYes — GetKeyAtIndex, GetValueAtIndex.No — no positional access.
Best forMostly-static, read-heavy sorted data.Frequently mutated sorted data.
