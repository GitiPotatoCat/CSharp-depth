ImmutableQueue<T>

A persistent FIFO queue built from two immutable stacks — one for enqueuing at the back, one for dequeuing at the front. Every Enqueue and Dequeue returns a new queue; the old one is still usable. Enqueue is always O(1); Dequeue is O(1) amortized — the only occasional cost is when the back stack has to flip to the front.

Enqueue
O(1)
push onto the back stack
Dequeue
O(1) amortized
pop front; flip when empty
Peek
O(1) amortized
reads front head

When to use

Reach for ImmutableQueue when FIFO order matters in a snapshot-based model — event sourcing where each processed event yields a new queue, deterministic replay of message streams, undo-aware task pipelines. For multi-writer concurrent producer-consumer, ConcurrentQueue is dramatically faster. For a single-threaded mutable queue, plain Queue<T> wins on raw throughput.

How it works

front stack (reversed for dequeue) back stack (enqueue onto top) ┌───┬───┬───┐ ┌───┬───┬───┐ │ a │ b │ c │ ◄── Peek / Dequeue │ f │ e │ d │ ◄── Enqueue └───┴───┴───┘ └───┴───┴───┘ top → bottom top → bottom when front stack is empty, flip back onto front: reverse back stack (O(n)), but each element is flipped exactly once across its lifetime — O(1) amortized
Amortized, not worst-case
Individual Dequeue calls can be O(n) when the front stack is empty and the back stack has to be reversed onto it. Across the lifetime of any element, this happens exactly once — so the amortized cost remains O(1). For latency-sensitive systems that can not absorb the occasional spike, keep the queue short or batch dequeues during a quiet period.

Example

// Construct — factory or LINQ suffix
ImmutableQueue<string> q = ImmutableQueue.Create("fetch", "parse", "write");
ImmutableQueue<string> empty = ImmutableQueue<string>.Empty;

// Enqueue — returns a new queue
ImmutableQueue<string> q1 = q.Enqueue("send");

// Dequeue returns both the new queue and the removed item
ImmutableQueue<string> q2 = q1.Dequeue(out string first);
Console.WriteLine(first);                  // "fetch"

// Peek — read the head without removing
string head = q1.Peek();                   // "fetch"

// Iteration yields items head → tail (insertion order)
foreach (var job in q1)
    Console.WriteLine(job);

// Drain pattern — loop until empty
while (!q1.IsEmpty)
{
    q1 = q1.Dequeue(out var next);
    Process(next);
}

// Versioned processing — every state stands on its own
ImmutableQueue<Event> state0 = ImmutableQueue<Event>.Empty;
ImmutableQueue<Event> state1 = state0.Enqueue(new Event("login"));
ImmutableQueue<Event> state2 = state1.Enqueue(new Event("click"));
ImmutableQueue<Event> state3 = state2.Dequeue(out Event processed);
// state0..state3 all exist — structurally shared
