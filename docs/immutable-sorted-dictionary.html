ImmutableSortedDictionary<TKey, TValue>

An immutable key-value map with keys in comparer-defined order, backed by a self-balancing AVL tree. Every mutation returns a new dictionary that shares most of its nodes with the old one. Enumeration is always stable — keys come out sorted, revision after revision.

Lookup
O(log n)
tree descent by comparer
Add / Set
O(log n)
rebuild spine, share nodes
Remove
O(log n)
rebuild spine, rebalance

When to use

Use ImmutableSortedDictionary when the map must evolve over time and enumeration order must be predictable — config snapshots that ship to logs, incremental index builders, event-sourced projections with sorted output, any audit-visible state. For unordered immutable lookup, ImmutableDictionary is leaner per entry. For single-threaded ordered maps without revision semantics, SortedDictionary<K,V> wins on raw speed.

Stable order is the whole point
Where ImmutableDictionary orders keys by hash (and may even shift order across revisions), ImmutableSortedDictionary guarantees enumeration in comparer order for every revision. Set KeyComparer at construction to lock the order — StringComparer.Ordinal for byte-sorted keys, StringComparer.OrdinalIgnoreCase for case-insensitive, or a custom IComparer for domain rules.

Example

// Construct — factory, CreateRange, or LINQ suffix
ImmutableSortedDictionary<string, int> scores = ImmutableSortedDictionary
    .CreateRange(new[]
    {
        KeyValuePair.Create("dan",   91),
        KeyValuePair.Create("alice", 88),
        KeyValuePair.Create("carol", 95)
    });

ImmutableSortedDictionary<string, int> empty =
    ImmutableSortedDictionary<string, int>.Empty;

// Enumeration is sorted — alice, carol, dan
foreach (var (k, v) in scores)
    Console.WriteLine($"{k}: {v}");

// O(log n) lookup
if (scores.TryGetValue("alice", out var s))
    Console.WriteLine(s);

// Mutations return a new dictionary — original untouched
ImmutableSortedDictionary<string, int> added =
    scores.Add("bob", 72);
ImmutableSortedDictionary<string, int> updated =
    scores.SetItem("alice", 90);
ImmutableSortedDictionary<string, int> removed =
    scores.Remove("dan");

// Bulk edits via AddRange / SetItems / RemoveRange
ImmutableSortedDictionary<string, int> many = scores.AddRange(new[]
{
    KeyValuePair.Create("eve",   84),
    KeyValuePair.Create("frank", 77)
});

// Efficient batch construction via a Builder
ImmutableSortedDictionary<string, int>.Builder builder =
    ImmutableSortedDictionary.CreateBuilder<string, int>();
for (int i = 0; i < 1_000; i++)
    builder[$"user-{i:D4}"] = i;
ImmutableSortedDictionary<string, int> sealed = builder.ToImmutable();

// Custom ordering — descending keys via reversed comparer
ImmutableSortedDictionary<int, string> desc = ImmutableSortedDictionary
    .Create<int, string>(Comparer<int>.Create((a, b) => b.CompareTo(a)));

Key comparer recipes

GoalComparer
Default ascendingOmit — uses Comparer<TKey>.Default.
DescendingPass a reversed comparer — Comparer<T>.Create((a,b) => b.CompareTo(a)).
Byte-ordered stringsStringComparer.Ordinal — fastest for predictable audit output.
Case-insensitiveStringComparer.OrdinalIgnoreCase.
Custom key typeImplement IComparable<TKey> on the key or pass IComparer<TKey>.
