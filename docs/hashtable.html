Hashtable

A non-generic hash-based map from object keys to object values — the pre-generics ancestor of Dictionary<K,V>. Distinct from Dictionary: reads are lock-free and safe for concurrent readers, missing keys return null instead of throwing, and both keys and values are boxed when they are value types.

average, hash-based
Insert
O(1)

Use Dictionary<K,V> instead
Hashtable predates generics. Every key and value lives as object — value types are boxed at insert, unboxed at read, and the compiler cannot stop you from storing a mismatched type. Dictionary<K,V> is strongly typed, faster, and has a richer API. Hashtable remains only for COM interop, legacy serialization, and the occasional reader-safe map where switching to ConcurrentDictionary is overkill.

When to use

Only when a legacy API forces your hand — a COM interop surface, a serialized .config payload, or a very old library. New code should reach for Dictionary<TKey,TValue> for single-threaded access and ConcurrentDictionary<TKey,TValue> when multiple threads write. The one small niche Hashtable still fills is reader-heavy caches where writes are rare: reads need no locks by design.

Example

// Construct and populate — any key, any value
var config = new Hashtable();
config["host"]    = "localhost";
config["port"]    = 8080;           // int — boxed
config["enabled"] = true;           // bool — boxed

// Missing key returns null — no exception
var missing = config["unknown"];    // null

// Indexer returns object — cast required
string? host    = (string?)config["host"];
int     port    = (int)config["port"];     // unbox
bool    enabled = (bool)config["enabled"];

// Safe membership check
if (config.ContainsKey("host"))
    Console.WriteLine("ok");

// Remove is safe even when the key is absent
config.Remove("port");
config.Remove("never-there");          // no throw

// Enumerate yields DictionaryEntry, not KeyValuePair
foreach (DictionaryEntry e in config)
    Console.WriteLine($"{e.Key} = {e.Value}");

// Case-insensitive keys via custom providers
var ci = new Hashtable(
    StringComparer.OrdinalIgnoreCase);

// Synchronized wrapper — coarse locking for writers
Hashtable safe = Hashtable.Synchronized(config);

// Bridge to the modern world
var typed = config
    .Cast<DictionaryEntry>()
    .ToDictionary(e => (string)e.Key!, e => e.Value);

Hashtable quirks

QuirkBehavior
Missing keyReturns null silently — Dictionary<K,V> throws KeyNotFoundException.
Enumeration typeYields DictionaryEntry — not KeyValuePair<K,V>.
Reader safetyOne writer and many readers is safe without locks — a property Dictionary does not offer.
Null keysDisallowed — adding a null key throws ArgumentNullException.
Null valuesAllowed — both reads of missing keys and explicit null values return null, so the two cases are indistinguishable.
Custom hashingConstructor takes IEqualityComparer for case-insensitive or custom equality.
