ConcurrentDictionary<TKey, TValue>

A fully thread-safe hash-based map. Reads are lock-free; writes acquire one of many fine-grained locks, so independent keys rarely contend. Offers atomic upsert helpers — AddOrUpdate, GetOrAdd, TryUpdate — that compose cleanly under contention without any external locking.

Lookup
O(1)
lock-free, hash-based
Insert
O(1)
amortized, striped lock
Delete
O(1)
by key, striped lock

When to use

Reach for ConcurrentDictionary whenever multiple threads may write to the same map — caches, per-request state, shared counters, deduplication across producers. Prefer ImmutableDictionary when the common path is read, with rare atomic snapshot swaps. Reach for plain Dictionary protected by a lock only when every operation is a compound read-modify-write that the atomic helpers cannot express.

Factory delegates are not serialized
The factory passed to GetOrAdd or AddOrUpdate may run more than once for the same key under contention — only one result is stored, but the factory itself is not locked. Keep it side-effect free. When the factory is expensive or stateful, wrap the value type in Lazy<T> so all contending threads share a single evaluation.

Example

// Construct — optionally with concurrency level and capacity hints
var counts = new ConcurrentDictionary<string, int>();

// Atomic upsert — create on first hit, increment afterwards
counts.AddOrUpdate(
    key: "alice",
    addValueFactory:    _        => 1,
    updateValueFactory: (_, old) => old + 1);

// Lazy-initialized cache entry — factory runs at most once per key
var cache = new ConcurrentDictionary<int, Lazy<User>>();
User user = cache.GetOrAdd(
    42,
    id => new Lazy<User>(() => Load(id))).Value;

// Conditional update — only replace if the old value matches
bool replaced = counts.TryUpdate("alice", newValue: 10, comparisonValue: 9);

// TryRemove — atomic pop
if (counts.TryRemove("alice", out var last))
    Console.WriteLine(last);

// Enumeration is safe but yields a weakly consistent snapshot
foreach (var (k, v) in counts)
    Console.WriteLine($"{k} = {v}");

// Point-in-time snapshot
KeyValuePair<string, int>[] snapshot = counts.ToArray();

// Parallel population — safe without any external locking
Parallel.For(0, 10_000, i =>
{
    var key = (i % 100).ToString();
    counts.AddOrUpdate(key, 1, (_, old) => old + 1);
});

Atomic helpers at a glance

HelperSemantics
TryAddInsert only if the key is absent. Returns false if it is already present.
TryUpdateReplace only if the current value equals a comparison value — a compare-and-swap.
TryRemoveRemove and return the old value atomically, if the key exists.
GetOrAddReturn the existing value, or insert and return a new one. Factory may run more than once.
AddOrUpdateInsert when absent, transform when present. Both factories may run more than once under contention.

Enumeration semantics

AspectBehavior
Weak consistencyEnumerators do not throw on concurrent modification. They may reflect some, all, or none of the writes that happen during iteration.
CountTakes every internal lock. Treat as a diagnostic — never put it in a hot loop.
Keys / ValuesReturn a snapshot collection. Cheaper than Count but still O(n).
ToArrayProduces an immutable snapshot at a single moment — the safest way to capture state.
