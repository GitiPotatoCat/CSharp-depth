SortedList

The non-generic ancestor of SortedList<K,V> — a sorted key-value collection backed by two parallel arrays of object. Same design and same index-addressability as the generic version, but everything stored as object, so value-type keys and values are boxed and every read requires a cast.

Lookup
O(log n)
binary search on keys
Insert
O(n)
shift to preserve order
Delete
O(n)
shift after removal
Use SortedList<TKey,TValue> instead
The legacy SortedList stores every key and value as object — value-type keys and values are boxed, and every read requires a cast. The compiler cannot catch type mismatches. SortedList<TKey,TValue> offers the same array-backed design with full compile-time type safety and no boxing for value types. Use it for every new sorted map where writes are rare.

When to use

Only when legacy code hands you a System.Collections.SortedList that cannot be replaced — old Framework libraries, COM boundaries, serialized configuration from an ancient system. New code should reach for SortedList<K,V> for compact read-heavy maps, SortedDictionary<K,V> when writes are frequent, and plain Dictionary<K,V> when order does not matter.

Example

// Construct — keys must be mutually comparable
var scores = new SortedList();
scores["Dan"]   = 91;                // int values — boxed
scores["Alice"] = 88;
scores["Carol"] = 95;

// Indexer returns object — cast required
int alice = (int)scores["Alice"]!;      // unbox

// Missing key returns null — no exception
var missing = scores["Zane"];             // null

// Position-aware helpers — the legacy differentiator
object? firstKey    = scores.GetKey(0);        // "Alice"
object? firstValue  = scores.GetByIndex(0);    // 88 (boxed)
int    idxOfCarol = scores.IndexOfKey("Carol");   // 1
int    idxOf91    = scores.IndexOfValue(91);         // 2

// Read-only snapshots
IList keys   = scores.GetKeyList();
IList values = scores.GetValueList();

// Remove by key or by position
scores.Remove("Dan");
scores.RemoveAt(0);

// Enumeration yields DictionaryEntry in sorted key order
foreach (DictionaryEntry e in scores)
    Console.WriteLine($"{e.Key} = {e.Value}");

// Case-insensitive via IComparer
var ci = new SortedList(StringComparer.OrdinalIgnoreCase);

// Synchronized wrapper — coarse writer lock
SortedList safe = SortedList.Synchronized(scores);

// Bridge to the modern world
var typed = scores
    .Cast<DictionaryEntry>()
    .ToDictionary(e => (string)e.Key, e => (int)e.Value!);

Legacy quirks

QuirkBehavior
Missing keyIndexer returns null silently. The generic SortedList<K,V> throws KeyNotFoundException.
Enumeration typeYields DictionaryEntry — not KeyValuePair<K,V>.
Null keysDisallowed — adding a null key throws ArgumentNullException.
Null valuesAllowed, but indistinguishable from missing-key reads.
Position accessorsNamed GetKey / GetByIndex — renamed to GetKeyAtIndex / GetValueAtIndex in the generic version.
Key list viewsGetKeyList / GetValueList return live IList snapshots — equivalent to the generic version's Keys and Values properties.
