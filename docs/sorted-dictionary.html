SortedDictionary<TKey, TValue>

A key-value map backed by a self-balancing binary search tree (red-black tree). Enumeration always yields keys in sorted order, and every lookup, insert, and delete is O(log n). Choose it over Dictionary when ordered traversal matters and the map is written to as often as it is read.

Lookup
O(log n)
tree descent by key
Insert
O(log n)
locate and rebalance
Delete
O(log n)
remove and rebalance

When to use

Use SortedDictionary when keys must be enumerated in order and the map grows and shrinks often. For mostly-static data, SortedList<K,V> uses less memory and has faster lookups at the cost of slow inserts. For raw speed without ordering, plain Dictionary<K,V> wins on all three operations — reach for it first, and only switch to SortedDictionary when ordering is required.

Example

// Create with a collection initializer
var grades = new SortedDictionary<string, int>
{
    ["Dan"]   = 91,
    ["Alice"] = 88,
    ["Carol"] = 95,
    ["Bob"]   = 72
};

// Enumeration yields keys in sorted order — regardless of insert order
foreach (var (name, score) in grades)
    Console.WriteLine($"{name}: {score}");
// Alice, Bob, Carol, Dan

// O(log n) lookup
if (grades.TryGetValue("Alice", out var s))
    Console.WriteLine(s);

// Upsert — O(log n)
grades["Eve"] = 84;

// Remove — O(log n)
grades.Remove("Bob");

// Keys and Values collections are always in order
var sortedNames  = grades.Keys;     // Alice, Carol, Dan, Eve
var scoresByName = grades.Values;   // 88, 95, 91, 84

// Custom ordering via comparer
var desc = new SortedDictionary<string, int>(
    Comparer<string>.Create((a, b) => b.CompareTo(a)));

Ordering and comparer

GoalComparer
Default ascendingOmit the comparer — uses Comparer<TKey>.Default.
DescendingPass a reversed comparer — Comparer<T>.Create((a,b) => b.CompareTo(a)).
Case-insensitiveUse StringComparer.OrdinalIgnoreCase or a culture-aware comparer.
Custom key typeEither implement IComparable<TKey> on the key or supply IComparer<TKey>.
